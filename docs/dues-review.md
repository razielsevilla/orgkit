# Ticket P3: Verify or Reject Payment Submission

## Overview
Ticket P3 implements the officer verification workflow for student payment submissions in OrgKit. Officers inspect the submitted GCash reference number and receipt screenshot side-by-side with organization dues records, and either verify or reject the submission.

## Architecture & Data Model

### 1. `dues_payment_events`
An append-only audit trail capturing all lifecycle decisions and administrative reversals:
- `id uuid primary key default gen_random_uuid()`
- `payment_id uuid not null references dues_payments(id) on delete cascade`
- `org_id uuid not null references orgs(id) on delete cascade`
- `action text not null check (action in ('verified', 'rejected', 'undone'))`
- `actor_id uuid not null references auth.users(id)`
- `reason text null`
- `created_at timestamptz not null default now()`

### 2. Security Definer Functions
- `public.verify_dues_payment(p_payment_id uuid)`
  - Confirms caller is an officer of the organization (`is_org_member`).
  - Guards against self-review: an officer cannot verify their own dues payment.
  - Concurrency lock: atomically transitions `submitted` -> `verified`. If row was already decided by another officer, raises `already_reviewed`.
  - Appends audit event to `dues_payment_events`.
- `public.reject_dues_payment(p_payment_id uuid, p_reason text)`
  - Enforces mandatory reason (3 to 500 characters).
  - Atomically transitions `submitted` -> `rejected` with `reject_reason`.
  - Frees the member's partial unique constraint (`dues_payments_active_member_period_idx`), enabling resubmission.
  - Appends audit event to `dues_payment_events`.
- `public.undo_dues_payment_verification(p_payment_id uuid, p_reason text)`
  - Admin-only privilege: verifies caller is org admin (`is_org_admin`).
  - Reverts status `verified` -> `submitted` and clears review fields.
  - Records undo event with mandatory reason.
- `public.get_dues_review_queue(p_org_id uuid, p_period_id uuid)`
  - Returns `submitted` payments oldest-first (`submitted_at ASC`) with member full name and email.

### 3. Screenshot Storage Security
- Screenshots are stored in the private `dues-screenshots` Supabase storage bucket.
- Direct public access is blocked.
- Screenshots are loaded exclusively via short-lived signed URLs (5-minute TTL) generated by server actions after verifying officer permissions.

### 4. Responsive UI & Concurrency Handling
- Desktop: Master-detail split layout with pending count badge, reference copy button, full-size image viewer, and action buttons.
- Mobile (360px): Stacked view with full-width touch-friendly buttons (`min-h-[46px]`), no horizontal scrolling.
- Optimistic Updates: Verifying or rejecting immediately removes the card from the active queue; on concurrency failure (`already_reviewed`), state rolls back and the queue reloads automatically.
